# Управление событиями на основе ключевых слов

Система, которая слушает звук, распознаёт речь и **выполняет действия,
когда в речи прозвучали заданные ключевые слова**.

Сценарий из аннотации: играет песня, на экране певица и настенные часы.
Когда звучат слова «Часы остановились», стрелки замирают и появляется
подпись «А часы-то остановились!». Когда звучат «Ещё идут старинные
часы…» — стрелки снова идут.

Главная идея: **связь «ключевые слова → действие» хранится не в коде,
а в файле `config/rules.json`**. Поэтому таких связей может быть сколько
угодно — хоть сотня, — и ни одну не приходится программировать.

```bash
pip install -r requirements.txt
```

## Как это устроено

```
┌──────────────┐   порции PCM 30 мс
│  Источник    │  файл  или  микрофон
│    аудио      │
└──────┬───────┘
       ▼
┌──────────────┐   черновик (partial)  +  итоговая фраза (final)
│ Распознавание│   офлайн-модель Vosk, русский язык
│    речи      │
└──────┬───────┘
       ▼
┌──────────────┐   «Часы остановились!» → часы остановились
│Нормализация  │   «ЧАСЫ остановились»   → часы остановились
│    текста    │   «часы же остановились»→ часы же остановились
└──────┬───────┘
       ▼
┌──────────────┐   нечёткое сравнение, синонимы, порог уверенности
│  Поиск       │
│  ключевых слов│
└──────┬───────┘
       ▼
┌──────────────┐   подавление повторов, «только один раз», приоритет
│  Диспетчер   │
└──────┬───────┘
       ▼
┌──────────────┐   часы, подписи, смена сцены, звук, журнал, счётчики
│ Обработчики  │
└──────────────┘
```

### Почему нельзя искать слово обычным `if "часы остановились" in text`

Распознавание речи всегда ошибается, поэтому система не ищет подстроку,
а сравнивает **близость** (расстояние Левенштейна через `rapidfuzz`):

| Распознано | Правило | Сработает? |
|---|---|---|
| `часы остановились` | `часы остановились` | да, 100 % |
| `часы остановилис` | `часы остановились` | да, 96 % |
| `часы же остановились` | `часы остановились` | да, лишнее слово внутри |
| `Часы остановились` | `часы остановились` | да, регистр не важен |
| `певцы остановились` | `часы остановились` | нет, первое слово не то |

Кроме того система умеет:

* **синонимы** — у правила может быть несколько фраз;
* **падежи и числа** — «второй раз» и «2 раз» считаются одним словом;
* **временное окно** — слова «часы» и «идут», прозвучавшие с разницей
  в десять секунд, **не склеиваются** в фразу «часы идут»;
* **фразы на стыке** — если фраза «часы остановились» попала на границу
  двух распознанных фраз, она всё равно найдётся;
* **черновики** — событие срабатывает сразу, не дожидаясь конца фразы,
  но повтор по тому же месту подавляется, когда придёт итоговый текст.

## Правила

Файл `config/rules.json`. Одна запись — одно событие:

```json
{
  "id": "clock_stop",
  "action": "clock.set",
  "phrases": ["часы остановились", "стрелки остановились", "часы встали"],
  "payload": { "running": false, "caption": "А часы-то остановились!" },
  "threshold": 0.84,
  "cooldown": 4.0,
  "priority": 10
}
```

| Поле | Смысл |
|---|---|
| `id` | уникальное имя правила |
| `action` | какой обработчик вызвать |
| `phrases` | ключевые слова и их синонимы |
| `payload` | параметры, которые получит обработчик |
| `threshold` | минимальная схожесть 0..1 |
| `cooldown` | минимальный интервал между срабатываниями, с |
| `once` | сработать только один раз |
| `require_final` | ждать подтверждённой фразы, не реагировать на черновик |
| `enabled` | временно выключить правило |
| `priority` | приоритет при конфликте |

### Готовые обработчики

| Действие | Что делает |
|---|---|
| `clock.set` | останавливает / запускает стрелки часов |
| `caption.show` | выводит текст поверх картинки |
| `scene.set` | переключает сцену: `singer`, `clock`, `both`, `black` |
| `beep` | звуковой отклик |
| `stats.count` | увеличивает именованный счётчик |
| `log.write` | пишет строку в журнал |
| `media.pause` / `media.resume` / `media.stop` | управление воспроизведением |

Новый обработчик добавляется декоратором — и всё, он сразу доступен
в правилах:

```python
from handlers.base import Handler, handler

@handler("lights.on")
class LightsHandler(Handler):
    def handle(self, event):
        print(event.payload.get("color"))
```

## Команды

| Команда | Что делает |
|---|---|
| `python main.py gui` | графический интерфейс |
| `python main.py play ФАЙЛ` | прогон со звуком, в темпе записи |
| `python main.py run ФАЙЛ` | прогон без звука, максимально быстро |
| `python main.py mic` | работа с микрофоном |
| `python main.py check ФАЙЛ` | оценка точности и скорости |
| `python main.py rules` | показать загруженные правила |
| `python main.py test` | модульные проверки |
| `python main.py models` | состояние моделей распознавания |

Ключ `--final-only` заставляет систему реагировать только на
подтверждённые фразы, игнорируя промежуточные черновики.

## Структура проекта

```
core/                 ядро, не зависит от интерфейса
  audio.py            источники звука, воспроизведение
  stt.py              распознавание речи (Vosk)
  text.py             нормализация текста
  matcher.py          нечёткий поиск ключевых слов
  rules.py            загрузка правил из JSON
  events.py           шина событий
  engine.py           конвейер целиком
handlers/             обработчики событий
ui/                   графический интерфейс (PySide6)
  stage.py            сцена: певица, часы, подписи
  clock_widget.py     часы с остановимымися стрелками
  panels.py           журнал, текст, правила, статистика
  main_window.py      окно и рабочий поток
config/rules.json     правила
tools/                загрузка модели, создание демо-дорожки
tests/                модульные проверки
```

Ядро не знает про графику: оно работает и в консольном режиме, и в окне.
Распознавание всегда идёт в отдельном потоке, иначе окно перестало бы
отвечать; события разбираются в главном потоке по таймеру.

## Проверки

```bash
python main.py test
```

91 проверок без звуковой карты и без модели: нормализация текста,
загрузка правил, нечёткий поиск, шина событий, пересэмплирование

## Сотни правил

```bash
python tools/generate_rules.py 100 --run
```

Скрипт создаёт `config/rules_100.json` со ста правилами и замеряет
скорость поиска. Ни строчки кода при этом не меняется — меняется
только файл конфигурации.

Замер на этой машине: 100 правил, ~58 000 проверок правил в секунду.
Распознавание в реальном времени успевает за половину секунды, то есть
запас примерно двадцатикратный. Подключить такой набор:

```bash
python main.py gui -r config/rules_100.json
```

## Требования

* Windows 10/11, Python 3.10+
* `vosk`, `sounddevice`, `soundfile`, `rapidfuzz`, `PySide6`
* Модель распознавания: `vosk-model-small-ru-0.22` (~44 МБ) —

  точнее, но тяжелее.

## Если что-то пошло не так

**`does not contain model files` при загрузке модели.**
Vosk — это C++-библиотека, и на Windows она читает файлы только по
однобайтовым путям. Если проект лежит в папке с кириллицей
(например `C:\Users\Иван\...`), путь нужно латиницей. Программа
обходит это сама: при первом запуске модель копируется в кэш
`%LOCALAPPDATA%\KeyWordsDemo\` и загружается уже оттуда.

**`Не удалось скачать` при загрузке модели.**
Сервер отдаёт файл маленькими кусками. Загрузчик качает его в 16
потоков и повторяет неудачные блоки; прерванную загрузку можно
продолжить повторным запуском той же команды.

**`portaudio` / нет звукового устройства.**
Не установлен `sounddevice`. Выполните:
`pip install sounddevice`. Без звуковой карты работает только
проверка правил и модульные тесты: `python main.py test`.

**Черновики мелькают слишком часто.**
Используйте `--final-only` — система перестанет реагировать на
промежуточные результаты и будет срабатывать только на
подтверждённые фразы.
